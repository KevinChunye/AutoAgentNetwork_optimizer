# PHOENIX: dependency-constrained workflow recovery

This extension implements the 2026-10-31 recovery plan. The application is a real,
bounded scikit-learn classification workflow, not the superseded MaxRects experiment.
No quality improvement or model-capability difference is assumed.

## Install and verify without experiments

Use Python 3.12 (3.11+ is supported by the parent project):

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,phoenix]"
python -m pytest -q tests/test_phoenix_*.py
python -m autoagentnet.phoenix --help
```

The tests use temporary synthetic arrays, trusted CPU operations, and a deterministic
fake provider. They do not load the three scientific benchmark datasets, calibrate live
models, or execute the 360-branch study. Test-fixture scores are not experiment results.

The distribution's source snapshot is pinned to upstream
`0eb1b3b7437eda8544ae2e6b1626d90c5432e27d`. It contains the runtime/configuration source
needed by PHOENIX, not the upstream project's historical data/cache/ledger or full Git
history. For paid work, apply the supplied patch to an authenticated, up-to-date checkout
with its original ledger and normal state synchronization. Never invent an empty ledger.

## Implemented behavior

- Content-addressed, typed computation DAG: prepare → fit → predict → validate;
  two prediction branches may merge through an ensemble.
- Independent payload checks, immutable parameter/data/code signatures, parent hashes,
  UNVERIFIED verification, MISSING/STALE suffix rebuilding, and owner-version fencing.
- F0 stops a worker but preserves the model pool. F1 additionally withdraws an explicitly
  named model from every survivor. Shared tools and committed artifacts remain available.
- LLM proposals are restricted to a validated pipeline/ensemble DSL. They cannot provide
  measured scores, credentials, file paths, code, or new permissions.
- Full dependency closure, shared-prefix cost deduplication, empirical capability lookup,
  remaining-dollar/CPU normalization, receding-horizon selection and explicit incumbents.
- Six policies: fixed takeover, LLM recovery, full greedy, no-dependency ranking,
  no-cost ranking, static cost-aware repair. Fixed can continue with ordinary model-based
  design after its original jobs; it is not deliberately made to stall.
- Deferred design operations use any still-available registered model. A complete
  configuration in a proposal is used directly instead of paying to generate it again.
- Existing MarketCaller/LocalRuntime/registry/governor/cache/ledger/prereg gate; no new
  vendor SDK path. `aan estimate/check/run` recognizes `kind: phoenix`.
- Durable call intent and output, tool receipts, branch-local stores, resumable snapshots,
  terminal artifacts, reports, a held-out evaluator and an HTML event replay.

The artifact store loads joblib objects generated by the trusted local tool worker.
Do not import arbitrary third-party pickles as checkpoints. This is not an untrusted-code sandbox.

## Recovery interfaces

`Proposal` permits INHERIT, VERIFY, RECOMPUTE, REROUTE, SPLIT, ABANDON.
REROUTE contains one PipelineSpec; SPLIT contains two and a fixed soft-vote weight.
A REROUTE with `model` but no pipeline explicitly requests a deferred design call.

`compile_proposal` validates and expands these high-level forms. `compile_plan` returns
the complete executable closure, inherited artifacts, estimated future calls/tools,
success-weighted terminal gain and costs. The local new-computation dependency depth is
bounded at four, excluding valid ancestors; a split requiring a deeper entirely new path
is rejected until an appropriate prefix exists. Dynamic design reserves its whole future
CPU suffix before it can be chosen.

Capability observations are restricted to `partition: calibration`. Completion rates are
smoothed; quality samples are conditional on completion and include successful runs with
zero improvement. Fit/pipeline estimates use classifier category when supported, then
fall back to coarser development data. There is no online fitting on formal outcomes.

Greedy priority is expected positive terminal quality change divided by future API cost /
remaining API dollars plus future CPU / remaining CPU. Historical spend is sunk. The
no-cost variant keeps hard feasibility checks. The no-dependency variant ignores reuse
and sharing in ranking, while the common executor retains provenance safety and cache.

`enumerate_estimated` is a small-graph oracle under explicitly stated estimates: independent
operation-completion events, common events for shared ancestors, and comonotonic terminal
quality quantiles. It is not an oracle over held-out outcomes and has no optimality claim
for the greedy policy. It rejects more than eight plans or missing operations.

## Future experimental preparation — not performed during code delivery

The following commands actually prepare or run experiments and should be used only when
that work is requested. All paths below are relative to the repository root.

1. Prepare fixed train/validation/sealed-test partitions and training-internal calibration
   folds. Nothing reads the sealed file during recovery:

```bash
python -m autoagentnet.phoenix prepare --out data/external/phoenix
```

2. Create the 18 actual CPU checkpoints (three datasets × T1/T2 × seeds 101–103):

```bash
python -m autoagentnet.phoenix checkpoint \
  --data data/external/phoenix/wine/search.npz \
  --template T2 --seed 101 --out data/external/phoenix_checkpoints/wine_T2_101
```

Repeat this explicit preparation for breast_cancer/wine/digits, T1/T2 and 101/102/103.
Existing checkpoints are verified rather than overwritten with different states.

3. Generate the three 30-call calibration configs. Configure AAN_OPENAI_API_KEY and
   AAN_ANTHROPIC_API_KEY securely in the process environment; do not put values in YAML.

```bash
python -m autoagentnet.phoenix calibration-configs \
  --out configs/experiments/phoenix_calibration --data-root data/external/phoenix
python -m autoagentnet.phoenix freeze configs/experiments/phoenix_calibration/*.yaml
# Commit the implementation, input provenance and configurations, then use aan check/run.
```

Calibration uses genuine training-internal baseline observations. Design and diagnosis
return complete configurations; planning is tested through the bounded proposal DSL.
Every partial/failed outcome is retained. Incomplete or synthetic tables are refused for
production recovery. Combine the completed files with:

```bash
python -m autoagentnet.phoenix combine results/phoenix_calibration_*/capability_table.json \
  --out research/phoenix/capabilities.json
```

4. Generate the full matrix as DRAFT configurations, not as running jobs:

```bash
python -m autoagentnet.phoenix matrix --out configs/experiments/phoenix \
  --data-root data/external/phoenix \
  --checkpoint-root data/external/phoenix_checkpoints \
  --table research/phoenix/capabilities.json
```

E1: 216 F1 branches (six policies, two budgets, 18 paired cases).
E2/E3: 36 identity-only and 36 healthy controls.
E4: 72 same-proposal-pool selector branches. Total: 360.

Freeze actual checkpoint/table/config/template hashes and commit configs before paid
execution. E4's pool is deterministically the FIRST E1/full/$0.20 proposal for its case,
not the best-looking response. Extract it after its source exists, then freeze E4:

```bash
python -m autoagentnet.phoenix pool results/<E1-full-source> \
  --out configs/experiments/phoenix/pools/<case_id>.json
python -m autoagentnet.phoenix freeze <branch.yaml>
aan estimate <branch.yaml>
aan check <branch.yaml>
aan run <branch.yaml>
```

For a dry run on a prepared *fixture* checkpoint, use `--model-override fake`. It retains
model-reference identities so resource-withdrawal logic is exercised, but all providers
are replaced with offline clients and output is stored under `fake_<name>`.

Paid entry points repeat preflight for programmatic callers. Synthetic or partial tables,
changed hashes, dirty source, missing keys/ledger, disabled persistence and uncleared
preregs are refused. The scientific sub-budget is separate from the existing account/run
caps. Calls reserve worst-case cost before submission; actual independent logical cost
includes cached calls. Transport/cancellation uncertainty stops rather than silently retries.

## Held-out evaluation and report

All branches must first export a frozen executable predictor. Then seal the complete
study before reading held-out labels:

```bash
python -m autoagentnet.phoenix seal configs/experiments/phoenix/study_manifest.json \
  --out research/phoenix/evaluation_manifest.json
python -m autoagentnet.phoenix evaluate research/phoenix/evaluation_manifest.json \
  --out reports/phoenix/evaluation.csv
python -m autoagentnet.phoenix report configs/experiments/phoenix/study_manifest.json \
  --evaluation-csv reports/phoenix/evaluation.csv --out reports/phoenix
python -m autoagentnet.phoenix replay results/<branch> --out reports/phoenix/replay.html
```

The evaluator replays fitted predictors, never refits or selects with test labels. It
rejects changed frozen graphs/artifacts/split signatures. Scientific figures are generated
from score files. Missing runs remain explicit rows; an invalid first E4 pool is unavailable,
not an invitation to select a later proposal.

Per-run files: state.json, events.jsonl, calls.jsonl, trajectory.json,
recovery_plan.json, frozen.json, status.json, immutable artifact payloads/receipts.
`recovery_plan.json` records final reuse, execution order, model assignments, abandoned
tasks and still-deferred alternatives.

## Interpretation and limits

- The three datasets are controlled mechanism probes; they do not establish broad AutoML performance.
- F1 is a controlled model-resource withdrawal, not a claim that one worker dying naturally
  removes a provider account. A real capability gap must be measured, not presumed.
- Completion independence and the finite empirical quality table are approximations.
  Calibration error and planning overhead may erase any advantage.
- CPU timing includes process overhead. When a crash loses the parent's timing measurement,
  receipt recovery records internal worker CPU only, a lower bound missing startup overhead;
  such runs carry `cpu_accounting_incomplete: true`. CPU limits have normal OS scheduling/
  whole-second enforcement granularity.
- No failure detection, arbitrary generated-code execution, real network-partition handling,
  permission fabrication, online learning, RL, or claimed scheduling approximation guarantee.
- No full model calibration, scientific benchmark, or held-out study was run during delivery.
  A separately authorized two-call OpenAI integration smoke passed; see PHOENIX_SMOKE.md.
