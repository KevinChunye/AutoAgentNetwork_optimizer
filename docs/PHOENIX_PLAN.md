# PHOENIX：能力损失后的预算约束工作流恢复

版本：2026-10-31。用途：交给工程／研究执行者实施。本文替代此前以任务板接管、Self-or-Social Pruning 或排样策略搜索为核心的方案。

状态：研究设计，尚未实现、校准或获得效果数据。文中的示例数字用于解释算法，不是实验结果。本文不包含账户凭据或私人安排。

## 1. 目标、边界与 benchmark 选择

研究问题：系统失去一个成员或其提供的资源后，如何根据已完成工作、依赖、剩余能力和预算，选择继承、验证、重算、改道或放弃，以较少重复工作交付更好的最终结果？

方法输入：工作流图、实际 artifact 状态、可用模型／工具清单、开发阶段能力与费用统计、剩余 API 预算和计算时间。输出：具体恢复子图、执行者／模型分配、执行顺序、复用清单和放弃清单。输出必须能由普通程序执行和验证。

### 1.1 对原排样任务的判断

原 CLASS + MaxRects 策略搜索不作为本版主 benchmark：候选通常独立评测；共享的已验证结果不会因作者离线而失效；所有成员在同机拥有同一求解器时，退出一个身份没有自动消灭求解能力。候选谱系也不等于计算依赖——一个完整 JSON 策略通常不需要重放其父候选的搜索过程。

排样可以保留为同质、浅依赖的负对照，但不能支撑“复杂工作流重构与真实能力损失”的完整主张。本版建议将主应用改为机器学习实验工作流，这是一个新的、明确的 benchmark 选择，而不是声称旧任务已具备这些性质。

### 1.2 主应用：可执行的分类实验工作流

使用 scikit-learn 构造真实处理→训练→预测→验证→集成的依赖。候选配置、拟合后的转换器、训练模型、预测数组和验证报告都是实际 artifact。变更转换器会使依赖它的模型／预测需要新版本；只变更分类器不应强迫重算未变的转换器。

这是自建的受控恢复 benchmark，不冒称公认的 agent-recovery benchmark。小型公开数据用于机制验证，不声称代表生产级 AutoML 或重大科学发现。scikit-learn 官方也提示这些小数据不足以代表真实世界任务。

文档：https://scikit-learn.org/stable/modules/compose.html
数据：https://scikit-learn.org/stable/datasets/toy_dataset.html

## 2. 工作依赖图：什么保留、什么重验

### 2.1 图中记录什么

采用有类型的任务／artifact DAG。边表示实际读取或生成，不依据 LLM 自述随意创建。

```text
训练数据 + split
    → 拟合转换器 → 转换后的训练/验证特征
    → 模型拟合 → 验证预测 → 验证报告

模型 1 的验证预测 ─┐
                  ├→ 集成规则 → 集成验证报告 → 可执行最终预测器
模型 2 的验证预测 ─┘
```

LLM 的建议／失败分析作为证据节点，和“计算输入”使用不同边类型。建议者退出不会使其建议过的已验证成果失效。

最小节点字段：ID、类型、父 artifact ID、内容哈希、操作／参数哈希、训练／验证 split 哈希、代码与依赖版本、状态、验证规则、产物位置、实际费用与耗时、执行者。任务另有 owner 和 ownership version，防止迟到提交。

### 2.2 有效性分类

| 状态 | 判定 | 恢复行为 |
|---|---|---|
| VALID | 产物可读、签名匹配、所需验证完成 | 继承；计读取／校验成本，不重训 |
| UNVERIFIED | 产物已提交，但缺少对应验证收据 | 先验证，不能直接当成功结果 |
| STALE | 输入、参数、split、代码或父版本与待执行路径不一致 | 为新版本重算受影响后缀；旧版本仍可留给原路径 |
| MISSING | 没有可读取的产物，只有任务或元数据 | 必须重算或改道；不能把日志当产物 |
| RUNNING | 执行未完成 | 动作边界 shutdown 后转为未完成；不声称恢复未保存的内部状态 |

VALID 只表示在声明的规则下可复用，不是语义正确性的万能保证。版本签名和规则必须由执行器生成、验证器检查。

**Shutdown 本身不使后代成果失效。** 只有确实改变输入／版本或缺少必要产物时才重新计算。共享且持久化的文件保留；本版不额外删除文件来制造故障。

## 3. 剩余能力：硬可用性与软能力分开

### 3.1 资源模型

维护可用模型与工具注册表。每个动作声明所需接口、输入／输出类型、工具版本，以及估计费用和时间。

- 硬约束：模型端点是否可调用，工具是否安装且能通过探针，artifact 是否可读。
- 软能力：某模型完成配置设计、诊断或任务拆分的实测成功率、质量提升和耗时。
- 所有存活成员可选择全部仍可用的模型与工具，不因为角色 prompt 而禁止调用某个接口。
- 同一个模型在不同任务上的表现可以不同；不把型号贵、参数多或角色名当成功率。

候选模型沿用 AutoAgentNetwork 的引用：

| 引用 | 实际模型 | 用途 |
|---|---|---|
| luna_low_ev | gpt-6-luna，reasoning low | 常驻低成本规划／设计选项 |
| sol61_low | gpt-6.1-sol，reasoning low | 设计、诊断和改道选项 |
| sonnet_low | claude-sonnet-5-5，effort low | 跨供应商设计、诊断和改道选项 |

输出上限统一 4,096 tokens；不另设 temperature；输入估算不超过 6,000 tokens。执行前核对实际 registry、价格、访问权；不可用时不静默替换。

### 3.2 两种故障必须分别报告

**F0：纯身份 shutdown。** 停止一个 worker，但模型池、工具和共享产物均保留，存活 worker 可使用原模型池。这是必要负对照，可能被普通接管完全解决。

**F1：shutdown + 资源撤回。** 除停止 worker 外，统一执行器撤去 sonnet_low 或 sol61_low 的可调用性。这是预注册的“模型资源损失”注入，不能说成普通身份退出必然导致的后果。所有组都受相同可用性变化约束，不能借其他存活身份绕过端点撤回。

如果部署中没有真实隔离凭据／独占资源，就明确称为受控资源撤回，不声称复现真实权限丢失。工具不被人为分配成“仅 A 能训练、仅 B 能验证”；本版 CPU 工具对所有组公开。

如果 F1 前后在开发任务上没有可测的软能力差异，只能报告可用模型集合变小，不能声称已经证明实质能力下降。不能用角色提示、假失败或特意挑弱模型补造差异。

### 3.3 校准方式

在正式实验前，用训练集内部划分生成三类任务：配置设计、失败诊断、恢复子计划设计。每类每个模型运行 10 次，共 90 次调用；任务按三个数据集轮流分配。

每次由 schema、实际工具执行和验证反馈判定：可执行性、是否完成目标、验证分数变化、费用、CPU 时间。成功率使用 (成功次数+1)/(尝试次数+2) 平滑；质量分布在完成目标的样本中估计，包含没有改善的成功执行；失败概率另外估计，避免重复扣除失败。费用使用中位数，预算预留仍走最坏情况 governor。不可用格子回退到同动作类型的汇总开发统计，不能用测试结果填表。

能力表包含样本数，所有统计在正式实验前冻结。该表是小样本经验估计，不声称精准的能力测量；另报告估计与实际结果的误差。

## 4. 恢复算法：LLM 提案，显式算法选择

算法名称使用描述性名称“依赖约束的预算贪心恢复”，不宣称 DAG 或贪心是新算法。

### 4.1 动作定义

- INHERIT：复用签名匹配的 VALID artifact。
- VERIFY：为已提交但未验证的 artifact 补验证；验证失败后才考虑重算。
- RECOMPUTE：在现有接口和相同语义下补算缺失／过期后缀。
- REROUTE：替换模型、分类器或处理路径，生成保持交付契约的新子图。更改输入时相应后缀重新签名。
- SPLIT：将可分解任务展开为多个节点，例如分别生成候选、分别训练两个学习器，再合并预测。拆分要有可执行汇合规则，不能只是多段自然语言。
- ABANDON：停止一个非必需分支；不能删掉最终交付所需依赖。

所有动作按实际成本计费。已经发生的历史费用是 sunk cost，不进入“下一步是否值得做”的排序，只进入总成本报告。

### 4.2 提案与编译

每次提案由仍可用的 luna_low_ev 调用一次，最多提出三个局部替代子图，深度最多四个新操作。默认只在启动恢复、一个方案完成或失败后重新提案，最多三轮。

程序另生成三个确定性候选：沿原路径最小补算、先验证可用中间结果、从最佳已验证成果另开分支。加入“不再花费、交付当前合法最好结果”的选项。去重后每轮最多六个非空方案。

提案必须遵循固定操作 DSL 和现有 artifact 引用。程序检查循环、输入类型、可用接口、资源约束和最终预测器能否实际执行；LLM 不能给自己填写“成功率 0.99”或授予新工具。

若提案已经包含合法完整配置，直接使用，不强制再调用模型生成一遍。若仍有待完成的设计／诊断任务，记录为真正的后续模型调用节点。所有后续调用允许从存活模型池选择执行模型。

### 4.3 必须按“完成方案的依赖闭包”排序

对每个方案 pi：

1. 沿依赖回溯，得到完成可交付结果所需的完整闭包。
2. 跳过可继承的 VALID 产物，加入必要验证与缺失后缀。
3. 合并闭包中的共享工作，不能重复计费；替代路径只选择一个，不能把互斥方案相加。
4. 检查剩余能力。缺少执行者／工具则拒绝，或等待显式改道提案，不能假设之后会恢复。
5. 计算未来 API 成本 c(pi)、CPU 时间 t(pi) 和预计最终边际质量 g(pi)。

收益定义为：完成方案后，交付最好结果相对当前最好已验证结果的预期提升。按最终结果计收益，不按中间节点数、下游节点数或修复次数加分；多个候选汇合时不能把相关收益重复相加。

简单估计使用开发表中的完成概率与质量增量分布。多节点方案暂用条件类型统计的乘积近似成功率，并将其作为可检验启发式；不宣称独立性真实成立。估计过稀疏时使用汇总先验并标记，不能让 LLM 的信心替代校准数据。

具体采用 p_complete(pi) × E[max(0, Q_pi−q0) | 方案完成]；失败时交付仍为 incumbent，增量为零。估计在每轮相对新的 q0 重算，不直接沿用旧增量。若交付已有更优结果或方案只重复相同预测器，收益必须为零。

默认质量为验证集 balanced accuracy，范围 0–1。设当前最好值为 q0，估计方案交付质量为随机变量 Q_pi，则：

```text
g(pi) = estimated E[max(q0, Q_pi)] - q0

score(pi) = g(pi) / (c(pi)/B_remaining + t(pi)/T_remaining + 1e-6)
```

其中 B 为剩余 API 美元预算，T 为剩余 CPU 秒预算，归一化两项权重均为 1，测试前冻结。不将低置信估计变成证明；报告预测误差。

按 score 最大者选方案；平分先选未来美元成本低者，再选 CPU 时间短者，再按规范化方案哈希。预计完整闭包不能放入剩余预算的方案不执行。强制零成本继承先于排序。

每次模型调用还须满足其实际输入和输出上限对应的最坏费用预留，不能仅凭平均费用放行。预留不适配时尝试其他合法方案／执行模型；没有可行方案才停止。任务选择中不把这种预算拒绝当成模型能力失败。确定不再执行的非必需分支由程序标记为放弃，不为单独写一条 ABANDON 日志额外调用模型。

每次只执行选定方案的下一个就绪节点，实际结果写回后重算排序。方案集合仅在规定提案时点扩展；未完成方案保留，所以不会因一轮结束而忘记远期收益。始终以完整闭包估价，避免每次只做便宜前缀却永远不完成终点。

```text
while resources remain:
    validate provenance and reuse valid artifacts
    obtain/update bounded proposal set when required
    compile dependency closures and feasible assignments
    estimate marginal terminal gain and future cost
    choose highest-scoring feasible plan
    if all predicted gains are zero: stop with incumbent
    execute its next ready operation
    commit receipt, charge actual resources, update graph
```

这是滚动、带依赖约束的贪心启发式，没有最优性或近似比保证。通过小图上的枚举最优解比较，测它的次优程度。

## 5. 完整示例（数字均为说明性假设）

当前已经训练并验证一个模型 M1，验证 balanced accuracy=0.82。标准化器 P、变换后的特征 Xp 均已验证。另一模型 M2 已保存，但其预测 P2 和验证收据尚未完成。原成员 A 正在准备 M2 的改进／集成任务时退出；F1 同时撤去 A 提供的一个模型访问选项。

```text
train/split → P → Xp → M1 → P1 → V1(0.82)
                     └→ M2 → P2(未验证)
                          P1 + P2 → Ensemble → VE(未完成)
```

M1、P、Xp、P1 不因 A 退出而失效。若改变 P，只为新 P 创建新的 Xp／模型分支，不能把原模型直接接到新特征上。

剩余预算 $0.10、CPU 60 秒。提案编译后的三条可交付路径：

| 方案 | 实际需要做的工作 | 预计边际收益 g | 预计未来成本 | score |
|---|---|---:|---|---:|
| 继承并验证 | 保留 P/Xp/M1/M2，验证 P2，完成可执行集成 | 0.036 | $0.01，4 秒 | 约 0.216 |
| 重算原后缀 | 重新设计、训练和验证原分支 | 0.048 | $0.07，40 秒 | 约 0.035 |
| 改道 | 保留 P/Xp，换一个可由现有模型设计的分类器并训练验证 | 0.0425 | $0.03，10 秒 | 约 0.091 |

原来“继续调用已撤回模型”的方案直接不可行，不参与排序。继承并验证方案优先，其收益是最终集成质量提升，不是“验证了几个节点”。

假设执行后实际验证值为 0.855，剩余预算更新为 $0.09／56 秒。所有方案相对 0.855 重新算收益。之后可能选择改道；如果再支出 $0.03 后只剩 $0.06，则 $0.07 的原后缀重算方案不可行，放弃该分支并交付当前最好结果。

此例说明算法如何作决定，不预设真实实验中“继承并验证”一定优于重算。如果 M2 无法验证，必须重新规划；不能继续使用 0.855 这样的假定结果。

## 6. 可执行 benchmark 规格

### 6.1 数据与隔离

MVP 固定三个 sklearn 内置分类数据集：load_breast_cancer、load_wine、load_digits。无需外部数据下载。它们用于受控机制实验，结果逐数据集报告。

每个数据集使用 random_state=42 分层划分 60% train、20% validation、20% test：先分出 20% test，再从剩余 80% 中分出 25% validation。fit 的所有统计只读 train。规划和方案选择可读 validation 分数；test 标签由独立最后评分程序持有。

能力表和成本表只在 train 内部用种子 1、2、3 的 80/20 内层划分校准。正式运行使用随机种子 101、102、103，不变更外层 split；这些是同一数据集上的运行重复，不是三个新数据集。

冻结数据 hash、行索引、包版本、配置空间和种子。正式开始后不修改验证指标、收益估计器或提案提示。

### 6.2 固定可执行配置空间

- 处理器：passthrough、StandardScaler、MinMaxScaler。
- 降维：无，或 PCA，n_components 取 0.90／0.95／0.99，固定 svd_solver=full。
- 分类器：LogisticRegression（C∈{0.1,1,10}，max_iter=1000）、RandomForest（n_estimators∈{50,100}，max_depth∈{None,5,10}，n_jobs=1）、KNeighbors（n_neighbors∈{3,5,11}）。
- 集成：两个已训练、可重放预测器的软投票，权重取 0.25／0.50／0.75；不任意拼接数组，不训练读取 test 的选择器。
- LLM 仅输出固定 DSL 和配置，不执行生成代码。多步方案可拆分已有操作；不能添加新 Python、库或未声明的数据访问。
- 每个工具操作在子进程运行，30 秒超时；所有线程与 random_state 固定。超时和失败的 CPU／模型成本照计。

### 6.3 两类真实 checkpoint

T1：链式工作流。保留转换器和训练特征，已有一个合法 incumbent；第二个模型已拟合但预测／验证尚未完成。

T2：共享前缀与汇合工作流。两个学习器共享同一已拟合处理器；一个分支已验证，另一个分支刚保存待验证 artifact；集成尚未完成。

checkpoint 由实际工具逐步执行并在动作边界暂停得到，不用手写“成功产物”。待验证状态表示确实缺少验证收据，不假造错误。每个 checkpoint 保存一个合法 incumbent；初始配置由固定程序按种子抽取，不筛选有利故障点。

三个数据集 × 两类 checkpoint × 三个运行种子 = 18 个配对 case。主 F1 的撤回模型按规范化 case 顺序交替选择 sonnet_low、sol61_low，共各 9 个；luna_low_ev 始终作为存活成员的低成本规划选项。

### 6.4 预算与停止条件

主实验两个未来 API 预算：$0.05、$0.20。每分支另外最多 120 CPU 秒、20 分钟墙钟、8 次模型调用、24 个工具操作；先到者停止。全部规划、选择、诊断和修复调用都占模型额度与美元预算。

初始 checkpoint 和开发校准费用分别列出；独立部署总费用必须加回，不能靠共享前缀称部署免费。节点实际 cache 命中仍记录读取成本；本次新增账单与逻辑独立运行成本分开。

执行前用开发 cost table检查两个预算是否造成不同的可行方案集合。若两个预算下所有计划始终都可行或全不可行，停止正式实验并明确修改预注册；不在看到正式效果后调预算。包和模型的运行时验证也是前置门槛。

## 7. 对照组与实验矩阵

### 7.1 六个主方法

| 方法 | 决策方式 |
|---|---|
| Fixed takeover | 已验证成果保留；未完成原分支按拓扑顺序补完；执行模型不可用时使用开发阶段冻结的可用替代顺序；预算不足则交付 incumbent。没有无限重试或故意卡死 |
| LLM recovery | 相同可用模型、工具、图、预算和统计；LLM 自行选择下一恢复方案，可继续／验证／重算／改道／放弃，实际执行仍过同一安全检查 |
| PHOENIX full | 本文的提案、依赖闭包、能力过滤和收益／成本贪心 |
| PHOENIX no-dependency | selector 忽略跨节点复用和共享前缀，按完整路径名义成本估价；执行器仍检查真实依赖并允许同样的合法 cache，不能制造错误成果 |
| PHOENIX no-cost | 仍检查硬预算和能力，仅按预计最终收益排序，不用成本作优先级 |
| Static cost-aware repair | 无额外 LLM 规划；只用三个确定性候选，选择未来费用最低的可完成补算路径；相同图、cache 和资源。这是强工程基线 |

no-dependency 检验的是依赖信息对规划与估价的作用，不声称证明没有依赖安全检查也能运行。no-cost 不能越过同一预算。主方法不能独享验证器、成功率表或更强模型。

### 7.2 公平性与选择器专项实验

主实验比较端到端政策，提案／选择的额外成本全部计入。LLM recovery 可以把方案与选择放在同一次调用；不强迫它购买对自己无用的额外提案。

额外做同候选集的选择器检查：每个 case 固定一次提案结果，对 full／no-dependency／no-cost／LLM selector 提供相同候选子图。它隔离选择机制，不能替代端到端主结果。共享提案的逻辑成本各组照计；实际新支付费用另计。

对不超过八个未完成操作的小图，枚举所有合法恢复路径与执行模型组合，使用相同开发估计比较贪心与估计最优解的差距。这是估计模型下的调度 oracle，不是知道真实测试分数的性能上界。

### 7.3 运行规模

- E1 主资源损失：18 cases × 六个方法 × 两个预算 = 216 分支。
- E2 纯身份退出负对照：18 cases × Fixed/full × $0.20 = 36 分支。
- E3 健康条件：18 cases × Fixed/full × $0.20 = 36 分支。
- E4 同候选集 selector 检查：18 cases × 四个 selector × $0.20 = 72 分支；提案冻结后再运行，不对所有可能动作穷举付费。
- E5 小图枚举／单元测试：离线，不消费模型费用。

合计 360 条逻辑分支，上界 2,880 次恢复阶段模型调用；能力校准最多 90 次、接口 smoke 最多 12 次，checkpoint 由程序生成。实际调用可因停止、固定规则或精确缓存减少。成本先估算，预算不适配时不得默认全部执行。

所有方法按 case 配对；同一 case 的所有分支使用完全相同的 checkpoint、故障目标、可用性、数据和 budget。分支运行顺序用种子 2026 的固定随机排列，控制服务时段影响；付费 run 仍按仓库要求串行。

## 8. 指标与结论规则

主指标：固定未来预算下，最终可执行预测器的 test balanced accuracy。方案只按 validation 选择；最终评分程序只评估已冻结预测器，不能让策略用 test 挑结果。没有新成果则评 incumbent；失败分支不删除。

核心报告：full−Fixed、full−LLM 在同 case／预算的质量差，以及相应费用差，给出 Pareto 图。只有质量不差且成本较低的具体点才能叫该条件下支配；没有显著差异不等于质量等效。

辅助指标：

- 必需重算成本：因输入／版本确实改变或产物缺失而执行的节点成本。
- 冗余重算成本：同一语义签名已有可访问 VALID 产物却重新执行的成本；所有组允许相同 cache，结果可能都接近零。
- 验证成本单列，不能把合理验证一律算重复工作。
- 有效复用率：实际使用的合法旧产物／可用于该交付路径的合法旧产物；不奖励无关 cache。
- 恢复到首个合法交付／首个严格更好验证结果的美元、CPU、墙钟成本。未达到按未达到报告。
- 无效调用、不可执行方案、预算超限尝试、图约束拒绝数。
- 规划开销：提案／选择占总费用比例；收益、成本和成功率的预测误差。
- 健康→F0、健康→F1 的质量与成本变化，区分身份故障、资源损失和普通搜索优势。

逐数据集列出各 case 配对差值、平均值、中位数和胜／平／负。三个数据集不足以支持广泛跨任务泛化；同一数据上的 split／运行重复不当作新数据集。小样本结果以描述性和条件性结论为主，不靠大量相关模型调用制造显著性。

预期可以为负：完整共享下 fixed 足够好；资源撤回没有实质能力差异；贪心输给成本优先；校准误差抵消规划收益；小数据计算太便宜导致规划开销不划算。均保留并报告。

## 9. 实施顺序与仓库接入

基础仓库：https://github.com/KevinChunye/AutoAgentNetwork 。此前核对版本：0eb1b3b7437eda8544ae2e6b1626d90c5432e27d。正式实现先检查最新版本、工作区和规范；本文不假设已实现恢复能力。

1. 数据／DSL／checker：固定三数据集 split、预处理与分类器空间、可执行预测器交付契约。先实现确定性基线，跑通 train→validation→最终 test 的隔离。
2. Artifact DAG：内容寻址、版本化、验证收据、分支副本、所有权 fencing。完成 artifact 继承／重验／后缀重算测试。
3. 资源与故障注入：实际探针、模型池、F0/F1；确认撤回后没有绕过，其他资源不受影响。
4. 恢复编译器与贪心：闭包、共享成本去重、替代路径、预算检查；先用已知小图和枚举验证，再接 LLM 提案。
5. 各基线与消融：同一工具执行器、数据权限、cache 和计费路径。补同候选集专项实验。
6. 接 API 与 CLI：新增 kind: phoenix；接入 aan estimate/check/run，复用 MarketCaller、LocalRuntime、ProviderRegistry、SpendGovernor、PriceBook、Ledger、CallCache、gate_problems 和正常状态持久化。
7. 校准与预检：能力统计、费用统计、预算区分度、DSL 解析、实际可用性。预检不通过则先停止，不伪造 capability gap。
8. 冻结提交：配置、模型、能力表、数据、提案模板、收益／成本规则、故障和矩阵。通过 fake dry run、预注册、预算 gate 后运行。
9. 结果与展示：按日志生成指标、调度轨迹和一条真实恢复回放，不手填效果数字。

所有供应商调用只经仓库现有路径；不在新模块直接导入厂商 SDK。密钥从 AAN_OPENAI_API_KEY／AAN_ANTHROPIC_API_KEY 读取，不保存到配置或 artifact。运行前读取当前 budget／steering／ledger；不修改受保护价格、预算或手改账本，不绕过单 run 与账户 cap。按当前研究协议完成审计、预注册及 state 同步；若凭据、预算或同步能力缺失，先完成离线工作并记录阻塞。

分清科学实验的未来预算 B 与仓库单 run cap：前者是 $0.05／$0.20 的实验条件，由 runner 在每次调用前检查；后者沿用实际配置。estimate 必须针对受该 B 限制的自适应运行给出保守账户费用上界，而不是假定所有可选模型都会各自运行满八次；可保守为每个可能账户预留 B，并把共享前缀及校准配置单列估算。预注册和 gate 仍全部保留。

最小类型／接口：Artifact、Operation、CapabilityProfile、RecoveryPlan、compile_plan、estimate_plan、select_plan、execute_ready_operation。操作收据包含输入签名、输出哈希、执行模型／工具、预计与实际成本、状态。最终输出包含图 patch、复用与废弃清单、拓扑执行顺序及模型分配。

## 10. 必须通过的验收测试

- 作者退出后，正确共享的 VALID artifact 仍可使用。
- 修改处理器版本只影响依赖它的新后缀；不能错误复用旧特征训练的模型。
- 只修改分类器时，原转换器和匹配特征可复用；共享前缀不重复计费。
- UNVERIFIED 必须验证；MISSING 不能用日志替代；验证失败触发重规划。
- 未完成任务释放，owner version 失配的迟到提交被拒绝。
- F0 保留模型池，F1 撤回真实调用选项；两个条件的日志可区分。
- 拆分有真实中间产物和汇合规则；改道满足输入／输出契约；必需终点依赖不能被放弃。
- 贪心估完整闭包，不被便宜死路前缀诱导；中间节点没有重复终点收益。
- 预算包括提案与失败调用；停止时仍保留合法 incumbent；子进程超时有收据。
- Fixed 在可行条件下正常恢复；LLM 组具有相同信息与权限；消融不绕过执行安全检查。
- test 标签／评分不出现在 proposal、selector 或能力表中。
- 一条离线闭环：真实 checkpoint→F0/F1→方案选择→执行／重规划→冻结 predictor→独立 test 报告。
