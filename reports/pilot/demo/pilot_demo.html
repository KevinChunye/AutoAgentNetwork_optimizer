Pruning a 19-agent Claude Haiku 5.5 network, stage by stage

Where does the network's accuracy come from, and how should a budget of agent calls be spent across stages and across tasks, in cache-aware dollars? The pilot is finished. On four BIG-Bench Extra Hard tasks, the 19-call team beat one Haiku call on the gate but not on held-out problems, and one Sonnet 5.5 call matched it at 1.25× the cost. This page shows the mechanism, the cost bounds and the results.

Why a whole grid is affordable

Configs that share an upstream sub-network reuse its calls from the call cache, so each task needs far fewer distinct calls than separate runs would. The v2 grid needs fewer still.

The gate: a task where 19 agents beat one

Before pruning, the dense network must beat a single agent by at least 5 points on the same problems, with the single agent at 30 to 60%. The literature scout shortlisted three task sets; each is prepared with fixed splits and a separate banding pool used only to choose the difficulty window from single-agent runs.

What prior work says

Novelty holds only re-scoped: closest is MaAS, which learns per query how many operators each layer runs, under a token-cost penalty. Nobody has compared joint search with stage-by-stage sensitivity at matched cache-aware cost, and a September 2026 audit finds learned pruners often no better than random pruning. So matched random pruning becomes the primary control.
